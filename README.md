# 理科 評価規準ジェネレーター

高校理科の年間指導計画・シラバス作成を支援する、ブラウザだけで動作する評価規準生成ツールです。学習指導要領上の中項目と小項目を選択データとして保持し、固定のテンプレートから3観点の評価規準を生成します。

## 対応科目

- v1.1：物理基礎（7中項目）、物理（12中項目）

科目を選択すると、学習指導要領に示された正式な科目目標を確認・コピーできます。

## 評価規準生成ルール

- **知識・技能**：「【中項目】について、【小項目一覧】を理解するとともに、それらの観察、実験などに関する技能を身に付けている。」
- **思考・判断・表現**：「【中項目】について、観察、実験などを通して探究し、規則性や関係性を見いだして表現している。」
- **主体的に学習に取り組む態度**：「【中項目】に主体的に関わり、科学的に探究しようとしている。」

AIによる言い換えは行わず、同じ選択からは常に同じ文章を生成します。入力内容や生成結果は保存・送信されません。

評価規準の文章は、学習指導要領上の中項目・小項目を基に、定型ルールで生成しています。

## 使い方

`index.html` をブラウザで開くと利用できます。科目と指導項目を選択し、各カードまたは「3観点をまとめてコピー」ボタンで文章をコピーしてください。

## 年間時数配分

「年間時数配分」タブでは、学校を選ぶとその学校の科目・単位数・週時数が表示されます。初期設定として三本木農業恵拓高校、三戸高校、五所川原工科高校、鰺ヶ沢高校を収録し、「その他」では任意の学校名・科目名も入力できます。標準年間時数は単位数（1単位あたり35時間）から自動計算され、単元指導計画時数とは別に管理されます。各月の授業可能日数を入力すると、授業実施見込みと、標準年間時数を月別に比例配分した年間指導計画用の時数を計算します。月別の整数配当には最大剰余法を用いるため、配当の合計は標準年間時数と一致します。

入力内容（単位数、週時数、月別授業可能日数）は学校IDと科目IDの組み合わせごとにブラウザの `localStorage` に自動保存され、学校や科目を切り替えて戻った場合も復元されます。単元指導計画時数は同じ学校ID・科目IDに保存された単元指導計画の配当時数を自動集計します。授業実施見込みから単元指導計画時数を引いた値を、実際の運用上の「不足見込み」または「余裕見込み」として表示します。標準年間時数との差は補助情報であり、授業実施上の余裕を表すものではありません。なお、**授業実施見込みは曜日未確定段階での概算です**。

## 単元指導計画

「単元指導計画」タブでは、所属・氏名を入力し、科目・単元を選択すると、学習指導要領に基づく単元の目標と評価規準を自動表示し、各時間の学習活動、評価観点（○：形成的評価、◎：総括的評価）、評価方法を入力して単元指導計画を作成できます。作成した計画はテキスト形式でまとめてコピーできます。

「Word形式で出力」では、`public/templates/unit-plan-template.docx` を読み込み、入力した単元指導計画を `.docx` として保存します。テンプレートの配置方法と利用できるタグは [`public/templates/README.md`](public/templates/README.md) を参照してください。テンプレートが未配置の場合も、Word出力時にエラーを表示するだけで、ほかの機能はそのまま利用できます。

計画は学校ID・科目ID・単元IDの組み合わせごとにブラウザの `localStorage` へ自動保存されます。学校、科目、単元を切り替えたりページを再読み込みしたりしても、それぞれの入力内容が復元されます。探究物理は学校ごとに独立した科目として管理され、現在は単元名を手動入力できます。所属・氏名は全単元共通の情報として、同じブラウザ内へ別途保存されます。

単元情報には、現在選択中の学校・科目で保存済みの全単元の「実授業時数 合計」を表示します。未保存の単元は0時間として扱い、配当時数を変更すると合計と年間時数配分タブの単元指導計画時数に反映されます。

### 単元の授業実施順と考査範囲

学校・科目ごとに「単元の授業実施順」を設定できます。初回は学習指導要領に基づく既存の単元定義順を表示し、「↑ 上へ」「↓ 下へ」で並べ替えた順序を `rika-teaching-order-v1:{学校ID}:{科目ID}` としてブラウザの `localStorage` に保存します。「初期順に戻す」を押すと保存した順序だけを削除し、既定順へ戻します。単元ごとの配当時数、学習活動、評価、Word出力用データは変更しません。

考査範囲の自動候補、範囲終点の選択肢、選択・確定範囲の必要時数、余裕・不足は、この授業実施順に沿って算出されます。順序を変更するとページを再読み込みせず再計算します。確定済みの範囲終点は同じ単元・同じ時間が存在する限り保持し、その終点までの必要時数だけを新しい順序で計算し直します。

## 年間行事

「年間行事」タブでは、既存の学校プリセットと年度を選び、開始日、終了日、任意の行事名、区分、通常授業を実施できるか、メモを登録できます。開始日を選ぶと、空欄の終了日には同じ日付が自動入力されます。行事名を省略した場合は区分名を表示します。登録済みの行事は日付順に表示され、一覧から編集・削除することもできます。

行事は `rika-annual-events-v1:{学校ID}:{年度}` というキーでブラウザの `localStorage` に構造化データとして保存されます。学校と年度ごとに保存先が分かれるため、切り替えると該当する行事だけが読み込まれます。

選択した学校・年度・科目の通常時間割から、年度（4月1日～翌年3月31日）の予定授業コマを生成します。「通常授業を実施できない」行事の日に重なるコマを除外し、通常時間割ベース予定、年間行事による除外、行事反映後の授業実施見込みを表示します。重複する行事があっても同じ日付・時限は1回だけ除外し、除外一覧には該当する行事名をまとめて表示します。この値は年間行事タブ内だけの見込みで、年間時数配分や単元指導計画には連携しません。

## 年間行事PDFの候補確認

「年間行事」タブでPDFを選択すると、全文・日付別抽出結果の下に「年間行事候補」を表示します。候補は表示月（すべて／4月～翌3月）と区分で絞り込めます。日付別抽出結果の月フィルターとは独立しています。

候補抽出は `annual-events.js` の `inferAnnualEventCandidates(cells)` が担当し、`{ date, month, day, text }` 形式のセルを受け取ります。PDF座標解析・セル復元は変更していません。`annual-event-candidates-ui.js` は、PDF抽出結果が表示されるタイミングで全日付行をセル形式に変換し、候補関数に渡します。読込中・クリア・読込失敗時には以前の候補を消します。

- 改行・セミコロンで別行事を分割します。中点・読点・空白は行事名の一部として保持します。キーワードの途中で折り返された場合は限定的に連結します。

- 放課後の委員会、PTA会議・委員会、部活動集会、健康診断、検診、検定試験、進路相談会、模試、講習を含む行は除外します。包含・除外ルールは同ファイルの定義に集約しています。

### 期間候補の整形

`annual-event-candidate-periods.js` の `prepareAnnualEventCandidates(candidates)` は、既存関数が生成した候補だけを入力とする純粋な後処理です。`startDate` / `endDate` を付加し、単日は同じ日付にします。

- 同一タイトル（全角・半角・空白差を吸収）・同一区分を日付順にまとめます。欠けた日が土日または `national-holidays.js` に収録された祝日のみなら結合します。通常の平日や未収録の祝日は飛ばしません。別行事が間に表示されていても、同一行事の連続日をまとめられます。
- 統合は実際に抽出された日付で判定し、その後に原文とタイトルの `～8/23` / `〜8/23` / `~8/23` から終了日を推定します。月日が開始日より前なら翌年です。全角数字・折り返しに対応し、実在しない日付は推定しません。
- `～13日` は開始月の13日が開始日以降の場合だけ推定します。不明な表記、複数の終了日が不一致、推定終了日より後に抽出日がある場合は `endDate: null` として「終了日要確認」を表示します。
- `needsReview` / `reviewReason` に曖昧な期間、通常授業可否の未確定、学校行事の学年・科目差、元候補の確認理由を保持します。夏季休業の開始が6～9月外、冬季休業が12～2月外、春季休業が3～4月外の場合も確認対象にします。季節名を自動修正しません。
- `sourceText` と `title` は原文どおり保持し、`sourceDates` / `sourceTexts` に統合元を日付順・重複を残して格納します。`sourceCandidates` に元候補の全フィールドのコピー、`observedEndDate` に最後の抽出日を保持します。
- 休業日区分の候補には `duplicateWarning: true` を付け、祝日一括追加との重複可能性を表示します。保存済み行事との照合は行いません。

候補一覧には期間・抽出した行事名・区分候補・通常授業・要確認・判定理由と、統合前後の件数を表示します。月フィルターは開始月だけでなく期間に含まれる月に一致します。終了日が不明な場合は確認できた抽出日までで絞り込みます。

候補は確認専用です。登録ボタンはなく、`rika-annual-events-v1:{学校ID}:{年度}` を含め、候補の保存・既存行事の変更・授業時数への反映は行いません。

### テスト

`node --test` で単体テストを実行できます。`node --test --test-isolation=none` では個別のテスト名・件数も表示します。候補ルールと期間整形には連続日、土日・既知祝日、平日を飛ばさないこと、月年またぎ、終了日表記、曖昧・無効・矛盾した期間、季節名、学年差、元情報保持、誤結合防止、月フィルター、保存しないことのテストを含めています。実PDFの候補数は実際の対象PDFを読み込んで確認してください。

## GitHub Pagesで公開する

1. GitHubリポジトリの **Settings → Pages** を開きます。
2. **Build and deployment** の Source で **Deploy from a branch** を選択します。
3. 公開するブランチと `/(root)` を選び、**Save** を押します。

ビルド工程や外部サーバーは不要です。
